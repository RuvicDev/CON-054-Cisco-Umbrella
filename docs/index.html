¿Qué es y para qué sirve?

El conector Cisco Umbrella permite que el agente de Ruvic use la plataforma de seguridad DNS y filtrado web de Cisco para investigar dominios, bloquearlos y revisar actividad reciente de la red. A diferencia de la mayoría de conectores, Umbrella no expone una sola API: combina tres APIs independientes, cada una con su propia credencial. Una vez configurado, puedes pedirle al agente cosas como:

  • "Consulta la reputación de evil-example.com antes de que lo abramos."
  • "Bloquea el dominio phishing-falso.com en la política de la organización."
  • "¿Qué actividad DNS sospechosa hubo en las últimas 24 horas?"

Operaciones soportadas:

Operación Qué hace API de Cisco Umbrella
security.query_domain Consulta reputación y categorización de seguridad de un dominio (solo lectura) Investigate API
security.add_to_blocklist Agrega un dominio a la lista de bloqueo real de la organización (escribe datos) Enforcement API
security.get_activity Consulta actividad DNS/web reciente por ventana de tiempo (solo lectura) Reporting API v2
add_to_blocklist modifica datos reales query_domain y get_activity son de solo lectura. add_to_blocklist SÍ escribe: agrega un destino real a la política de bloqueo de tu organización. El agente debe confirmar contigo antes de bloquear un dominio si no lo pediste explícitamente.

Prerrequisitos

  • Una organización activa en Cisco Umbrella (paquete DNS Security Essentials/Advantage o Umbrella Secure Internet Gateway, según tu contrato).
  • Acceso de administrador al panel de Umbrella (dashboard.umbrella.com), al menos durante la configuración inicial, para generar las tres credenciales.
  • La Enforcement API habilitada en tu organización (algunos planes requieren activarla en Policies → Security Settings → Integrations antes de poder generar la Customer Key).
  • El Organization ID de tu cuenta de Umbrella.
  • Salida de red desde la plataforma Ruvic hacia los dominios investigate.api.umbrella.com, s-platform.api.opendns.com y api.umbrella.com (habitualmente sin restricciones adicionales, ya que Ruvic sale por HTTPS estándar).

Configuración en el fabricante

Este conector usa tres APIs independientes de Cisco Umbrella, cada una con su propia credencial y su propio lugar en el panel. Genera las tres antes de pasar a la sección "Configuración en Ruvic". Si una falla, las otras dos capacidades del conector siguen funcionando con normalidad.

API 1 — Investigate (consultar reputación de dominios)

Usada por: query_domain. Es de solo lectura.

  1. Entra al panel de Umbrella: inicia sesión en dashboard.umbrella.com con una cuenta de administrador.
  2. Ve a Admin → API Keys → Umbrella Investigate: en el menú lateral, abre Admin y luego API Keys; selecciona la pestaña o sección de Umbrella Investigate.
  3. Crea el token: pulsa Create (o Generate) y copia el token generado de inmediato — Umbrella solo lo muestra una vez. Este token se usa como Bearer token.
[ Captura: Admin → API Keys → Umbrella Investigate — reemplazar por assets/img/investigate-api-key.png ]

API 2 — Enforcement (agregar dominios a la lista de bloqueo)

Usada por: add_to_blocklist. Escribe datos reales en la política de bloqueo.

  1. Ve a Policies → Security Settings → Integrations: en el menú lateral, abre Policies, luego Security Settings y busca la sección Integrations.
  2. Habilita la Enforcement API: pulsa Enable (si aún no está activa). Umbrella genera una Customer Key única para tu organización.
  3. Copia la Customer Key: guárdala de inmediato en un gestor de contraseñas; es la credencial que autoriza escribir eventos de bloqueo.
[ Captura: Policies → Security Settings → Integrations → Enforcement API — reemplazar por assets/img/enforcement-key.png ]

API 3 — Reporting v2 (consultar actividad reciente)

Usada por: get_activity. Es de solo lectura y usa OAuth2 client credentials.

  1. Ve a Admin → API Keys → Umbrella Reporting/Management: en el menú lateral, abre Admin → API Keys y selecciona la sección de Umbrella Reporting/Management.
  2. Crea una clave con rol Read-Only Reporting: pulsa Create, elige el alcance/rol Read-Only Reporting (no un rol de administración) y confirma.
  3. Copia el par Key + Secret: Umbrella muestra un Key y un Secret; cópialos de inmediato, el Secret no vuelve a mostrarse completo. Con este par el conector obtiene un access token OAuth2 automáticamente.
[ Captura: Admin → API Keys → Umbrella Reporting/Management — reemplazar por assets/img/reporting-key.png ]

Organization ID

Visible en Admin → Account Settings, o en la propia URL del dashboard cuando navegas dentro de tu organización (patrón /o/<org_id>/). Es un número, no una credencial secreta, pero es obligatorio para get_activity.

Permisos requeridos

Principio de mínimo privilegio: cada una de las tres credenciales solo necesita el alcance mínimo para su capacidad. No uses cuentas ni roles con permisos de administración general de la organización.

Credencial Alcance mínimo Para qué la usa el conector
Investigate API Key Solo lectura — consulta de reputación/categorización, sin acceso a políticas ni usuarios query_domain
Enforcement Customer Key Agregar destinos a la lista de bloqueo únicamente; no administra políticas completas ni usuarios de la organización add_to_blocklist
Reporting Key + Secret Rol Read-Only Reporting — sin permisos de administración de la organización get_activity
Credenciales independientes Las tres credenciales son independientes entre sí: si una falla o se revoca, las capacidades basadas en las otras dos siguen funcionando con normalidad.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Cisco Umbrella y pulsa Configurar. Diligencia el formulario con los seis campos, usando los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Investigate API Key El token generado en Admin → API Keys → Umbrella Investigate (paso 3 de la sección anterior)
Enforcement Customer Key La Customer Key de Policies → Security Settings → Integrations → Enforcement API
Reporting API Key El Key del par generado con rol Read-Only Reporting
Reporting API Secret El Secret del mismo par. Se guarda cifrado como secreto: la interfaz no volverá a mostrarlo
Organization ID El ID de tu organización (Admin → Account Settings o URL del dashboard)
Timeout de conexión Opcional; 15 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma consulta un dominio de referencia (cisco.com) vía la Investigate API para confirmar que al menos esa credencial funciona.

[ Captura: formulario del conector Cisco Umbrella en Settings → Conectores — reemplazar por assets/img/umbrella-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión hace un query_domain("cisco.com") vía la Investigate API. Si responde con datos de categorización, la tarjeta del conector cambia a estado Configurado. Este test solo valida la Investigate API Key; las otras dos credenciales se validan al usarlas por primera vez.

  2. Prueba con el agente.

    Abre una conversación nueva con el agente y pídele:

    "Consulta la reputación del dominio cisco.com en Umbrella."

    El agente debe responder con el status (-1 malicioso, 0 desconocido, 1 benigno) y las categorías de seguridad, si las hay. Si lo hace, la Investigate API quedó operativa de punta a punta.

  3. Prueba opcional de las otras dos APIs.

    Pide al agente "revisa la actividad de la red en las últimas 24 horas" para validar la Reporting API. Prueba add_to_blocklist solo con un dominio de prueba y solo si entiendes que modifica la política real de bloqueo.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"Credenciales inválidas o sin permiso suficiente" al consultar un dominio Falla la Investigate API Key: expiró, se revocó o se copió mal. Genera un nuevo token en Admin → API Keys → Umbrella Investigate y actualízalo en el formulario del conector.
"Credenciales inválidas" al intentar bloquear un dominio, aunque query_domain funciona Falla la Enforcement Customer Key específicamente (las tres credenciales son independientes). Verifica que la Enforcement API siga habilitada en Policies → Security Settings → Integrations y que la key en Ruvic sea la correcta.
"Credenciales inválidas" al consultar actividad reciente, aunque las otras dos capacidades funcionan El par Reporting Key/Secret es incorrecto o el rol no es Read-Only Reporting. Regenera el par en Admin → API Keys → Umbrella Reporting/Management y actualiza ambos campos en el formulario.
Token OAuth2 de Reporting expirado o inválido en medio de una sesión larga El conector renueva el access token automáticamente 30 segundos antes de expirar; si el error persiste, el Reporting Key/Secret configurado ya no es válido — regenéralo siguiendo el punto anterior.
"No se pudo alcanzar Cisco Umbrella" (timeout de red) La plataforma Ruvic no pudo conectar a tiempo con investigate.api.umbrella.com, s-platform.api.opendns.com o api.umbrella.com. Reintenta; si persiste, aumenta el timeout de conexión en el formulario o revisa el estado de servicio de Cisco Umbrella.
El conector aparece "Sin configurar" tras guardar Algún campo obligatorio quedó vacío (los seis campos excepto el timeout son requeridos). Ábrelo de nuevo y completa investigate_api_key, enforcement_customer_key, reporting_key, reporting_secret y org_id.

Preguntas frecuentes y notas de seguridad

¿El agente puede modificar mi política de seguridad sin que yo lo sepa?

Solo a través de add_to_blocklist, que agrega un dominio real a la lista de bloqueo de tu organización. El SKILL del conector instruye al agente a confirmar contigo antes de ejecutar esta acción si no la pediste explícitamente, y a mostrarte primero el resultado de query_domain cuando sea razonable. query_domain y get_activity son estrictamente de solo lectura y nunca modifican tu configuración.

¿Dónde quedan guardadas las tres credenciales?

Como secretos en el almacén de credenciales de la plataforma, asociados a tu usuario. La interfaz nunca vuelve a mostrarlas completas; solo indica "definida". Para cambiar una, escribe el nuevo valor en el campo correspondiente; para conservar las demás, déjalas vacías al editar.

¿Cómo roto cada credencial?

  • Investigate API Key: genera un nuevo token en Admin → API Keys → Umbrella Investigate y revoca el anterior; actualízalo en el formulario del conector.
  • Enforcement Customer Key: se rota deshabilitando y volviendo a habilitar la Enforcement API en Policies → Security Settings → Integrations (genera una nueva Customer Key).
  • Reporting Key/Secret: crea un nuevo par en Admin → API Keys → Umbrella Reporting/Management con rol Read-Only Reporting, actualízalo en Ruvic, y luego revoca el par anterior.

Recomendado rotar cada credencial cada 90 días o según tu política de seguridad interna.

Se comprometió una de las tres credenciales, ¿qué hago?

  1. Revoca de inmediato esa credencial específica en el panel de Umbrella (las otras dos no se ven afectadas, son independientes).
  2. Revisa la actividad reciente asociada en los registros de Umbrella (Reporting o el log de eventos de Enforcement, según el caso).
  3. Genera una credencial nueva siguiendo los pasos de la sección "Configuración en el fabricante" y actualízala en el formulario del conector.
  4. Si la credencial comprometida era la Enforcement Customer Key, verifica que no se hayan agregado bloqueos no autorizados a tu política.

¿add_to_blocklist afecta a usuarios reales de mi red?

Sí. Agregar un dominio a la lista de bloqueo mediante la Enforcement API modifica la política de seguridad real que aplica Umbrella a los dispositivos y usuarios de tu organización: cualquier intento de acceder a ese dominio será bloqueado de inmediato. No es una simulación ni un entorno de prueba.

Buenas prácticas Genera cada credencial con el alcance mínimo indicado en la sección de permisos; nunca compartas las claves por canales no seguros; revisa periódicamente los eventos agregados con add_to_blocklist; y trata cualquier compromiso de una credencial como un incidente de seguridad independiente de las otras dos.
